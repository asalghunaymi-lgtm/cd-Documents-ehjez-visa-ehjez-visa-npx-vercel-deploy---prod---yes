# Arabic / English (i18n)

The site is bilingual. **Arabic is the default** and keeps every existing URL unchanged;
English lives under the `/en` prefix.

| Arabic (default)         | English                     |
| ------------------------ | --------------------------- |
| `/`                      | `/en`                       |
| `/visa/uk`               | `/en/visa/uk`               |
| `/apply?country=france`  | `/en/apply?country=france`  |

No page was moved or duplicated: `proxy.ts` rewrites `/en/*` to the same page files and
passes the language to them in the `x-locale` request header.

## How it works

- **`proxy.ts`** — detects the language from the URL, rewrites `/en/*` (and adds a hidden
  `__lang` search param to both languages so the client router cache keeps the Arabic and
  English versions of a page apart — without it, switching language could show the old body), remembers the choice
  in the `NEXT_LOCALE` cookie (1 year), and sends a returning English visitor who lands on an
  Arabic URL to the English version.
- **`lib/i18n/config.ts`** — locales, cookie name, `localizeHref()` / `stripLocale()` helpers.
- **`lib/i18n/server.ts`** — `getI18n()` for server components and `generateMetadata`;
  `languageAlternates()` for canonical + hreflang tags.
- **`lib/i18n/client.ts`** — `useI18n()` and `useLocalizedRouter()` for client components
  (the language is read from the address bar).
- **`components/i18n/link.tsx`** — drop-in replacement for `next/link` that keeps the visitor
  in their language. Always import `Link` from here for internal links.
- **`components/i18n/language-switcher.tsx`** — the English / العربية button in the header.
  Switching is a client-side navigation, so text typed into forms is kept.
- **`components/i18n/html-lang-sync.tsx`** — updates `<html lang dir>` after a switch.

## Where the text lives

- **Interface text:** `lib/i18n/dictionaries/ar.ts` (source of truth) and `en.ts`.
  `en.ts` is typed against `ar.ts`, so a missing English string fails `npm run build`.
- **Content data:** Arabic stays in `lib/data/*` as before. English versions are in
  `lib/i18n/content/countries.en.ts` (country guides) and `lib/i18n/content/site.en.ts`
  (FAQs, pricing text, document checklist, nationalities, demo data).
  Prices, fees, official links, flags and dates are only stored once, in `lib/data/*`.
- Use the locale-aware accessors: `getCountries(locale)`, `getCountryBySlug(slug, locale)`,
  `getSiteFaqs(locale)`, `getPricingPlans(locale)`, `getDocumentRequirements(locale)`…
  (they default to Arabic, so existing calls keep working).

## Adding or changing text

1. Add the Arabic string to `ar.ts`, then the same key to `en.ts`.
2. Read it with `const { t } = await getI18n()` (server) or `const { t } = useI18n()` (client).
3. For a new country, add its English text to `COUNTRY_TEXT_EN` in `countries.en.ts`.

## Style notes

- English uses clear, professional British spelling (centre, authorised), which also
  matches UK Visas and Immigration terminology on the UK pages.
- Official names are never translated: UKVI, IRCC, VFS Global, TLScontact, BLS International,
  DS-160, MRV, ImmiAccount, Standard Visitor visa, Study permit.
- Directional icons that mean "forward"/"back" use `ltr:-scale-x-100` so they flip in English.
