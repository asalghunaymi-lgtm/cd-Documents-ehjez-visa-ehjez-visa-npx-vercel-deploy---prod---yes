# خارطة الطريق بعد MVP

هذا الملف يتتبع المراحل الـ 12 المذكورة في مواصفات المشروع، وما تم إنجازه في هذه الجلسة الأولى مقابل ما تبقى.

| # | المرحلة | الحالة |
|---|---|---|
| 1 | Landing Page احترافية | ✅ مكتملة |
| 2 | اختيار الدولة والتأشيرة (+ صفحات كل دولة) | ✅ مكتملة |
| 3 | إنشاء حساب | 🟡 واجهات جاهزة (`/login`, `/signup`)، المصادقة الفعلية تحتاج ربط Supabase Auth |
| 4 | إنشاء طلب (Wizard) | ✅ مكتملة (تعمل بحالة محلية، تحتاج حفظ فعلي في جدول `applications`) |
| 5 | رفع المستندات | ✅ الواجهة والفحص الأولي مكتملان، يحتاج ربط Supabase Storage فعليًا |
| 6 | Dashboard العميل | ✅ مكتملة (بيانات تجريبية، تحتاج استعلام حقيقي من `applications` + `application_status_history`) |
| 7 | Admin Dashboard | 🟡 هيكلة كاملة وواجهات تعمل، تحتاج ربط باستعلامات Supabase وصلاحيات حقيقية |
| 8 | Database + Supabase | 🟡 Schema + RLS + Seed جاهزة بالكامل في `database/`، بانتظار مشروع Supabase فعلي للربط |
| 9 | الدفع | ⬜ لم تُنفَّذ بعد — البنية جاهزة في جداول `invoices`/`payments`، يحتاج تكامل بوابة دفع سعودية (مدى/Moyasar/HyperPay) |
| 10 | الإشعارات | 🟡 واجهة تنبيهات تجريبية في لوحة العميل، الإرسال الفعلي (Email/SMS/WhatsApp) لم يُنفَّذ |
| 11 | المساعد الذكي | ⬜ لم تُنفَّذ بعد |
| 12 | تحسين SEO والأمان والأداء | 🟡 SEO أساسي مكتمل (Metadata, sitemap.xml, robots.txt, JSON-LD FAQPage)، الأمان الأساسي (RLS, بيئة منفصلة) جاهز في التصميم، يحتاج تدقيق أمني كامل بعد الربط الفعلي |

## أولويات الجلسة القادمة المقترحة

1. ربط مشروع Supabase فعليًا (تشغيل `database/schema.sql` + `policies.sql` + `seed.sql`) وتفعيل Supabase Auth
   لصفحتي `/login` و `/signup`.
2. استبدال البيانات التجريبية في `/dashboard` و `/admin/*` باستعلامات حقيقية.
3. ربط رفع المستندات فعليًا بـ Supabase Storage مع Signed URLs.
4. تكامل بوابة دفع سعودية لصفحة الفواتير.
5. تفعيل الإشعارات الفعلية (Email أولًا، ثم SMS، ثم WhatsApp عبر API رسمي فقط).
6. بناء المساعد الذكي بحيث يعتمد حصريًا على بيانات جدول `visa_requirements`/`document_requirements` المحدَّثة من
   لوحة التحكم، دون اختلاق أي معلومة.
